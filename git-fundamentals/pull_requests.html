🔀 Pull Requests

Un PR es una solicitud formal para fusionar código de una rama hacia otra. ¿Desde un fork o desde una rama? Ambas son válidas — depende del contexto.

¿De dónde viene un Pull Request?

ESCENARIO A

🤝 Rama interna → main

Cuando eres collaborator (tienes acceso de escritura), creas una rama dentro del mismo repo y abres el PR desde ahí.

  • Mismo repositorio
  • Sin fork necesario
  • Flujo de equipos internos
  • feature/auth → main
VS
ESCENARIO B

🌐 Fork externo → upstream

Cuando eres contributor externo (sin acceso de escritura), haces un fork, trabajas en él y propones el PR al repo original.

  • Repositorio diferente (tu fork)
  • Fork obligatorio
  • Flujo open source
  • you/repo:feature → owner/repo:main
💡 El ciclo interno del PR (revisión → CI → merge) es idéntico en ambos casos. Solo difiere el origen de la rama.

📋 Estado inicial — ramas independientes

La rama main tiene los commits C1, C2, C3. La rama feature/auth se creó desde C3 y tiene commits F1 y F2. Aún no hay comunicación formal entre ellas.
